## Editor Dogfood Checklist

- Open a trusted local workspace and confirm the Explorer tree, editor, Terminal, Problems, and Output panels render.
- Create a nested file, rename it inline, duplicate it, copy its path, reveal it, and delete it.
- Edit a Python file, confirm status bar dirty/line/column updates, save it, and run it.
- Edit a C++ file, confirm comments highlight as comments, review the run profile summary, and run it.
- Use Search and Go to Line from the editor toolbar and `Cmd/Ctrl+G`.
- Trigger diagnostics, filter Problems by active file, and click a diagnostic to jump to the line.
- Check Git diff for a modified file, then create and restore a snapshot with run evidence.
- Re-run release readiness after the editor pass; notarization and Windows E2E remain release blockers, not editor polish blockers.

## Deferred Social Entry Criteria

- Complete sustained Electron dogfood on a real project and attach `CODEYO_DOGFOOD_LOG` evidence.
- Keep `npm run desktop:verify:v0.1` green after editor polish changes.
- Decide whether Codeyo is local-first with optional social, or hosted/social-first with local IDE features.
- Define account identity, workspace membership, message storage, privacy, block/report behavior, and data deletion before implementation.
- Build social features against a deterministic local mock backend first; do not depend on manual testing against a live network path.
- Ship social in order: fixture UX prototype, mock backend contract, friend request, DM, presence, shared run/snapshot cards, then realtime collaboration/cloud sync.
